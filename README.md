# 🚨 Selected Project — ADMS

## Airline Disaster Management System

**ADMS — Airline Disaster Management System** is a research-oriented aviation software platform designed to explore how airlines can manage complex operational disruptions through **Digital Twins, decision-support systems, simulation, regulatory compliance, and intelligent recovery mechanisms**.

The project focuses on situations where airline operations deviate significantly from the planned schedule due to disruptions such as:

- Flight delays
- Crew unavailability
- Aircraft disruptions
- Schedule breakdowns
- Large-scale operational irregularities
- Regulatory constraints
- Cascading operational failures

ADMS is closely connected to my master's thesis and serves as a practical software environment for investigating **adaptive disruption recovery in airline crew operations**.

---

# 🪞 ADMS Digital Twin Architecture

At the core of ADMS is the concept of a continuously evolving **operational Digital Twin**.

```text
             REAL AIRLINE OPERATIONS
                      │
                      ▼
               Operational Data
                      │
                      ▼
        ┌─────────────────────────┐
        │     DIGITAL TWIN        │
        │                         │
        │ Flight State            │
        │ Crew State              │
        │ Duty State              │
        │ Aircraft State          │
        │ Regulatory State        │
        │ Disruption State        │
        └─────────────────────────┘
                      │
                      ▼
                Simulation
                      │
            ┌─────────┴─────────┐
            ▼                   ▼
       Scenario A           Scenario B
            │                   │
            └─────────┬─────────┘
                      ▼
              Constraint Engine
                      │
                      ▼
             AI / Optimisation
                      │
                      ▼
             Recovery Options
                      │
                      ▼
          Human Decision Maker
```

The goal is to represent the current operational environment digitally and use this representation to evaluate alternative recovery strategies.

---

# 🧩 ADMS Core Modules

## ⚖️ Compliance & Rule Engine

A rule-driven architecture designed to evaluate operational and regulatory constraints.

Examples include:

- Flight Time Limitations
- Duty limitations
- Rest requirements
- Crew qualification rules
- Operational restrictions
- Organisational policies
- Regulatory compliance

A core design principle is **fail-closed behaviour**.

If a critical rule is missing, ambiguous, or conflicting, the system should avoid silently generating assumptions.

---

## 🔬 What-if Simulation

ADMS includes a simulation-oriented environment for evaluating operational alternatives before execution.

Example scenarios:

```text
What happens if a crew member becomes unavailable?

What happens if a flight is significantly delayed?

Which crew recovery options remain legally feasible?

Will the proposed solution create a downstream duty violation?

How will the disruption propagate through the schedule?

Which alternative produces the lowest downstream operational impact?
```

---

The objective is to evaluate multiple recovery alternatives based on:

# 📊 Selected Project — FLEXBOX

## Reporting & Data Automation System

**FLEXBOX** is a modular **reporting, data processing, and automation system** designed to simplify repetitive analytical workflows and transform raw operational data into structured reports, dashboards, KPIs, and automated processes.

Unlike ADMS, which focuses on airline disruption management and decision support, FLEXBOX is primarily designed as a **general-purpose data and reporting automation platform**.

Its main purpose is to reduce repetitive manual work involved in:

- Data preparation

- Reporting
- KPI calculation
- Dashboard generation

# 🧠 Engineering Philosophy

I prefer building intelligent systems around four core principles.

### 1. Explainability

Operational users should understand why a system generates a recommendation.

### 2. Human-in-the-loop

AI should support human decision-makers rather than blindly replace them.

### 3. Constraint Awareness

Real-world optimisation must respect operational, regulatory, and organisational constraints.

### 4. Resilience

Systems should remain useful when operations deviate from ideal or expected conditions.

This philosophy is particularly important in aviation, where a mathematically optimal solution may still be operationally impossible.
